# JISかな入力変換（実験）

`experimental.text-jis-kana@1` / `TextJisKana`。管理Issue #89 の仕様案に基づく実験実装。正式採用・標準同梱は未決定で、この実装をもって昇格しない。

- 入力 `in` / 出力 `out`: ja / Text。設定はなし（空オブジェクト `{}` のみ有効）。未知キーは invalid-config。
- 入力は JIS X 6002（JISかな配列）のキートップ記号列とし、固定レイアウト表でかなへ変換する。出典は JIS X 6002 のキー配列で、表はコード内に固定する。
- 記号の約束: 基本面はキーの基本刻印（英小文字・数字・記号）。シフト面は、英字キーは大文字（ぃ=E、っ=Z のみ該当）、数字・記号キーはシフト側の刻印（ぁ=#、ぅ=$、ゃ='、ゅ=(、ょ=)、、=<、 。=>、・=? など）。
- 例外: 0 キーのシフト面（を）にはラテン刻印がないため、入力でも「を」そのもので表す。
- 濁点・半濁点: @ キー（゛）と [ キー（゜）、および入力に直接現れた U+309B / U+309C は、直前のかなと合成する。合成できない位置・対象では invalid-input。表にない記号は unknown-key。
- 代替可否の事前確認: text.mapping（#17）は状態を持たない固定置換で、合成処理とシフト面を表現できないため別kindとした（作業Issue #103 に記録）。OSのキーイベント取得は対象外。
- 出力の meta は付けない。Packet検証後に処理する。NoOutputはNoOutput。入力欠落はmissing-input、Text以外はinvalid-root。

検査: `cargo test --locked --all-features --test nodes_text_jis_kana`。正式fixtureを弱めず、このディレクトリーの契約例を実装に照合する。実Wasm検証とWindows CIの結果はPR側で確認する。

戻し方: 対象PRをrevertする。実験kindを使用したグラフは、別ノードへ交換してから実装を除去する。
