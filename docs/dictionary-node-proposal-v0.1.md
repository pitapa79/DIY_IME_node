## 1. 採用済み事項と当初の提案

| 区分 | 内容 |
| --- | --- |
| 採用済み | 本体を特定の辞書形式に固定しない。辞書データ、検索・候補生成、候補評価・選択は別の責務とする |
| 採用済み | 文章変換の受け渡しはPacketのText / Sequence / Choice。Choiceは同一Choice内で高いscoreを優先する |
| 採用済み | 既存 `e2e.*` の固定規則・小辞書・サンプルを維持する |
| 今回の提案 | 小さなテスト辞書を全文一致で検索し、表記候補のChoiceを返す独立ノード |
| 今回の提案 | UTF-8の簡単なTSV、入力原文のフォールバック、辞書の計画単位スナップショット |
| 未決定 | 正式kind・設定キー、外部ファイルの解決API、準備済みリソースAPI、TSVの正式仕様、上限の採用値 |
| 対象外 | 全文分割、最長部分一致、形態素解析、文脈コスト、学習、ユーザー辞書更新、複数辞書の統合、辞書の入手・同梱 |

TSVはこのノードの最初のテスト入力形式の候補であり、DIY_IME2全体の共通辞書形式にはしない。将来のSKK等の接続は別のノードまたは別タスクで扱える。

## 2. 最小の検索単位

入力Textの**全文と辞書のreadingが同じ場合だけ**一致とする。入力を語へ分割しない。`ほんじつ` が登録されていても `ほんじつです` の一部分だけを変換しない。

| 項目 | 初版の推奨案 |
| --- | --- |
| 仮称 | 完全一致辞書検索。正式kind / struct / versionは実装契約の採用時に決める |
| 入力 | 必須 `in`: text-packet@1、Text root、言語ja |
| 出力 | `out`: text-packet@1、Choice root、言語ja |
| 検索 | Unicodeの文字列をそのまま完全一致。大文字小文字変換、かな変換、NFC/NFKC、空白除去は行わない |
| 一致時 | 対応する全表記をTextの選択肢として、辞書内の行順で返す |
| 単一候補 | 1候補でもChoiceを返す。出力rootの宣言を一定に保つ |
| 未知語 | 入力と同じ文字列のTextを1つ持つChoice。scoreは省略する |
| 空入力 | 空Textを1つ持つChoice。成功したDataとして扱う |
| NoOutput | Nodeアダプターへ渡された場合はoutへNoOutput。必須入力の通常Engine実行ではSkipped |
| 不正入力 | 不正Packetはinvalid-packet、Sequence / Choice rootはinvalid-root |

検索は `RunContext.input.text` を直接読まず、接続ポートのTextを使う。compose / finalizeを見て暗黙に確定したり、pendingを結合したりしない。ローマ字変換から接続する場合、`out` に来た部分だけを検索する。これだけで全文のかな漢字変換やIMEの確定操作が完成するわけではない。

### 候補順とスコア

辞書のweightを、このテスト辞書ノード内では**同一reading内の表記の優先度**として定義し、その値をChoiceOption.scoreへそのまま設定する。有限の正数・ゼロ・負数を許可し、確率化や総和による正規化はしない。

候補を検索段階でスコア順に並べ替えない。候補選択ノードに渡した時、同点は辞書内の先頭となる。readingをまたぐ比較、他形式の辞書との尺度の互換性、形態素解析のコストとの換算は保証しない。既存の候補選択の `unscored` は未知語候補の評価に使えるが、このノードがその設定を変更することはない。

### 文字列とメタデータ

検索キー、表記、未知語の原文はUnicodeを変更せず保持する。例えば `が` と `か` + 結合濁点は別のキーであり、全角数字と半角数字も区別する。

初版案では、出力する全Textのmetaを省略する。辞書表記から元入力内のsourceSpanを推測しない。未知語も文字列の保存を保証し、入力metaの引継ぎは保証しない。入力Packet自体は変更しない。readingやsourceSpanを付ける要件が必要なら、実装契約の採用前に別途決める。

### 未知語の選択肢

| 案 | 利点・影響 |
| --- | --- |
| **原文を1候補として残す（推奨）** | 数字・記号・未知の文章も表示でき、辞書の未登録語で文章が消えない |
| NoOutput | 未登録を分岐条件に使えるが、下流の必須入力を止めるため、明示的な利用目的が必要 |
| エラー | 辞書の網羅性の検査に使えるが、通常入力で頻繁に失敗する |

最初の実装は原文保存だけでもよい。未知語ポリシーを設定に公開するかは未決定とし、下記の例に正式な設定キーは設けない。読み込みエラーを未知語扱いで隠すことは、どの案でも行わない。

## 3. 読込用TSVの提案

例は [entries.tsv](../examples/proposals/dictionary-exact/entries.tsv)。このリポジトリの提案用固定データであり、外部プロジェクトの辞書ではない。既存ノードが読み込むファイルでもない。

| 項目 | 推奨案 |
| --- | --- |
| 文字コード | 正しいUTF-8。先頭のUTF-8 BOMは1つだけ許容。置換文字による不正バイトの救済は行わない |
| ヘッダー | `reading`、`surface`、`weight` の3列をこの順で必須とする |
| 改行 | LF / CRLFを受け付ける。最後の行末改行は任意。裸のCRは拒否 |
| 区切り | タブ。各行は厳密に3列。引用符・エスケープ・コメント行・複数行フィールドは追加しない |
| reading / surface | 各1〜4096 Unicodeコードポイント。タブ・CR・LF・NULを含めない。前後の空白を削らず、空白だけの文字列も1つのキー・表記として扱う |
| weight | 有限の10進数。字句は `-?(0\|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?[0-9]+)?` 相当。前後空白、空欄、NaN、Infinity、桁区切りを拒否 |
| 同じreading・異なるsurface | 別候補として許可し、元の行順を保持 |
| 同じreading・同じsurface | weightが同じでも重複エラー。暗黙の統合・加算・後勝ち上書きを避ける |
| ヘッダーだけの辞書 | 有効な空辞書。すべての入力が未知語になる |
| 空ファイル・データ途中の空行 | 不正形式として拒否。最終改行そのものを空データ行に数えない |

weightは構文上正しくてもRustの有限数として表現できなければ拒否する。実装時にはパーサーと上限値を明示し、丸めで異なる値が同じscoreになった場合も元の行順を保つ。

### 上限の候補値

以下は小型テスト辞書向けの**提案値**。大規模辞書への一般的な制約として採用しない。超過時に行や候補を黙って切り捨てず、読み込み全体を失敗させる。

| 対象 | 候補値 | 単位・計測点 |
| --- | --- | --- |
| ファイル | 1 MiB | BOM・改行を含む生バイト。読み取り中も上限を検査する |
| データ行 | 10,000行 | ヘッダーを除く |
| 1行 | 64 KiB | 行末LF/CRLFを除くバイト数 |
| 同じreadingの候補 | 64件 | 重複検査後の表記数 |
| reading / surface / 検索入力 | 各4096文字 | Unicodeコードポイント数。UTF-16コードユニット数ではない |

ファイル全体の上限が先に達すれば行数が上限未満でも失敗する。入力Textの上限はRuntimeInput以外のsourceから接続した場合にも検査する案。境界値・異常系は実装タスクで検査する。

## 4. 読込時点、パス、計画との関係

**推奨する完成形は、prepare時に全件を読み込んで検査し、読み取り専用の辞書を計画へ固定する方式。** 入力のrunごとにファイルを開かず、同じ計画・同じ入力から同じ候補を返す。

ただし、現行 `Node::validate_config` は検査結果として `()` を返し、`Node::execute` は設定JSONを受け取る。[現行Node API](https://github.com/pitapa79/DIY_IME2/blob/1a385a9d9bfe0d2bcf083bf3bec35901a8d30133/crates/runtime/src/node.rs) と [実行計画](https://github.com/pitapa79/DIY_IME2/blob/1a385a9d9bfe0d2bcf083bf3bec35901a8d30133/crates/runtime/src/graph.rs) には、ファイルから準備した不変リソースをノードインスタンスごとの計画へ渡す専用の契約がない。`validate_config` で読み込むだけでは、その内容をrunで再利用できない。Registryの共有Nodeへ可変な辞書を保存する実装は、計画・インスタンス・タブ間の分離を壊すため採用しない。

| 実装の分け方 | 評価 |
| --- | --- |
| **まず純粋な読込・索引・完全一致検索を実装する** | 推奨する最初の小タスク。Node APIの変更を待たずにTSVと候補木の期待値を検証できる |
| 不変リソースをノードインスタンスの計画へ保持する仕組みを追加する | Nodeへ接続する前の依存タスク。正式な型・所有権・prepare失敗時の寿命を統合担当が設計する |
| ファイル内容を設定JSONへ展開する | 検査は容易だが、グラフ保存と辞書データを混ぜるため初版の完成形には推奨しない |
| 毎runでファイルを再読込する | レイテンシと再現性が不安定になる。IME向けの既定動作には推奨しない |

### パスの推奨案

- 相対パスの基準はホストが明示する**辞書用リソースルート**に統一する。CLIのカレントディレクトリ、エディターのサーバー位置、JSONの出所から暗黙に推測しない。
- 最初のローカル試作では、起動側が選んだ1つのルート配下のみを許可する案を推奨する。絶対パス、`..` によるルート外参照、リンク先のルート外参照、UNC・URLは初版では拒否する。
- JSONを別PCへ保存・移動しても辞書本体は含まれない。ルートの指定が必要ならホストで設定し、入力文章と共にrunへ渡さない。
- 正式な設定キー・CLIオプション・ホストAPI、Windowsのリンク/ジャンクションを含むパス検証方法は**未決定**。文字列の前方一致だけで配下を判定しない。解決後の実体を確認し、読み込んだハンドルの内容をスナップショットにする。

これは現在のCLI・エディターがすでに対応する機能ではない。上記を満たせるパス境界を設計するまで、Nodeの外部ファイル設定を公開しない。

### ファイル変更と復帰

1. prepareで読み取り、全行を検査し、不変の辞書を持つ新計画を準備する。読込中に内容が変わり得る外部ファイルについては、採用するスナップショット取得方法を依存タスクで決める。
2. activateまでは既存の稼働計画・辞書を維持する。prepare失敗時も稼働中の辞書を変更しない。
3. activate後は新しい計画・辞書を使う。ファイルが後から変更・削除されても既存のrunは保持済みの内容を使う。
4. 再読込は明示的な新prepare / activateとして扱う。ファイル監視・共有キャッシュ・自動更新は追加しない。
5. rollbackでは直前の計画とその辞書スナップショットへ戻す。run中に辞書内容を差し替えない。

辞書だけを更新してplanVersionを変えないAPIは、この案には含めない。辞書スナップショットの識別子・ハッシュの表示方法は、更新機構を設計する時に決める。

## 5. 失敗の区分案

コード名は実装契約で確定する**候補**。prepare時の失敗と、run中の入力・ノード失敗を区別する。どの失敗でも部分辞書を成功として公開しない。

| 失敗 | 検出時点 | 候補コード・表示内容 |
| --- | --- | --- |
| 不正設定 | prepare | invalid-config。必須キー・型・未知キーのどれが不正か |
| リソースルート未指定・外部参照 | prepare | dictionary-path。解決方針と問題の設定位置 |
| ファイル未存在・権限・読込失敗 | prepare | dictionary-read。ノードと辞書指定を識別できる情報 |
| 不正UTF-8 | prepare | dictionary-encoding。バイト位置。辞書本文全体は出力しない |
| 列数・ヘッダー・weight・空欄・重複 | prepare | dictionary-format。行番号と列名、重複なら最初の行も示す |
| 辞書の上限超過 | prepare | dictionary-limit。超えた上限名と候補値 |
| 不正Packet / root | run | invalid-packet / invalid-root。既存の診断経路を使う |
| 検索入力の上限超過 | run | dictionary-input-limit。入力の許容長を示す |
| 正常な未登録語 | run | 成功した原文候補。読込失敗とは分ける |

空入力・未知語でも、無効な辞書を使う計画のprepareを成功させない。読み込み問題を原文フォールバックで隠さない。

## 6. 提案例と受け入れテスト案

[提案例の説明](../examples/proposals/dictionary-exact/README.md)、[辞書データ](../examples/proposals/dictionary-exact/entries.tsv)、[検索例JSON](../examples/proposals/dictionary-exact/cases.json) を参照。`cases.json` はレビュー用で、`tests/contracts/` の採用済み契約例ではない。現行CLIで実行するグラフJSONでもない。

| 入力例 | 期待する動作案 |
| --- | --- |
| こうすい | 降水90、香水30、洪水90をこの行順で返す。後段の候補選択では同点の降水が先 |
| ほんじつです | 部分一致の本日は挿入せず、原文の1候補 |
| 30% | 辞書未登録なら数字と記号をそのまま1候補 |
| 空文字 | DataのChoice内に空Textを1つ。NoOutputと区別 |
| が / か + 結合濁点 | 登録した文字列と完全一致した方だけ一致 |
| Sequence / Choice入力 | invalid-root。形を勝手に走査・分割しない |

実装タスクでは次を自動化する。

- 検索: 全提案例、1候補・複数候補、行順、同点、負数、未知語、空入力、数字・記号・補助平面・結合文字、空白、入力metaを含む入力の不変性。
- 読込: LF/CRLF・BOM・行末改行ありなし、ヘッダーのみ、空ファイル、空行、未知列・不足列、不正UTF-8、weightの構文・非有限・オーバーフロー、同じreadingに異なる表記、重複したreading/surface。
- 上限: 各境界値と1超過。ファイルはメタデータだけでなく読取量も検査し、行・候補を切り捨てないこと。
- Node: NoOutput、必須入力のSkipped、不正設定、個別Registry、標準Registryへの統合後の実Engine、複数インスタンス・異なる辞書の分離。
- 計画: 同じ入力・計画での再現性、prepare失敗で旧辞書を維持、activate、ファイル削除・変更後も旧スナップショット維持、再prepareによる更新、rollback、別タブとの分離。
- 接続: ローマ字変換のja Text → 辞書Choice → [候補選択（Issue #4）](https://github.com/pitapa79/DIY_IME2/issues/4) → [文字列化（Issue #9）](https://github.com/pitapa79/DIY_IME2/issues/9)。両Issueの実装に合わせ、受け入れ条件を満たしたノードだけを使用する。

## 7. 実装前に決めることと小さな進め方

| 判断事項 | 推奨案 | 採用前に確認する点 |
| --- | --- | --- |
| 検索範囲 | 入力Text全文の完全一致 | 部分一致・分割を別タスクに分けることでよいか |
| 未知語・空入力 | 原文の1候補 / 空Textの1候補 | 空ChoiceやNoOutputにせず、文章を保持する方針でよいか |
| meta | 初版は全出力で省略 | 未知語のmeta保存やreading付与を初版に含める必要があるか |
| 辞書データ | この小型TSV案 | ヘッダー、重複拒否、有限weight、上限の候補値でよいか |
| 取得・更新 | prepareで固定、明示的な切替と復帰 | 不変リソースの所有権と、読取中の変更に対する取得方法 |
| パス | ホスト指定ルート配下の相対パス | ホストごとのルート設定、リンク・UNC・ルート外アクセスの扱い |
| 公開API | ノード固有の正式kind・設定を別途採用 | 辞書の共通管理APIへ早期に一般化しないこと |

推奨する実装の切り出し順は次のとおり。各作業を別Issue・ブランチ・PRにする。
